# 老前端与 Word 填写引擎清理

日期：2026-10-23。基于`b0b9d5a`，本轮按用户要求聚焦旧前端和填写引擎。

## 前端

原`web/index.html`有2953行，样式、流式请求、文件上传、预览与协同编辑混在一起。现在HTML保留页面结构；样式放到`styles.css`，脚本按以下职责拆分，继续由FastAPI静态服务提供，不引入框架、构建步骤或生产依赖：

| 文件 | 职责 |
| --- | --- |
| `js/state.js` | 会话、模板与字段状态；统一值转换、进度统计和复位 |
| `js/format.js` | 安全转义与消息格式化 |
| `js/chat.js` | 聊天、流式响应、超时与重试 |
| `js/preview.js` | 预览读取、字段映射、DOM更新和手工编辑 |
| `js/cofill.js` | 协同审核、手动字段卡片与确认生成 |
| `js/files.js` | 模板选择、文件上传、下载和打印 |
| `js/app.js` | 页面初始化 |

修复及简化：

- 新建对话只创建一个会话ID，统一清空文档、下载和字段状态；删除不存在的`addMessage`、`uploadedFiles`引用。
- 生成结果直接更新正在显示的消息，移除对不存在的`chatMessages`数组的`pop()`调用；失败恢复按钮状态，避免重复提交。
- 协同表单按字段ID保留、编辑、提交；不再按同名标签去重或覆盖。给Agent继续处理的手工数据也携带字段ID。
- 值转换、预览同步和进度计算统一；保留0、false和显式清空。批量更新只刷新一次进度，减少逐字段重复扫描。
- 审核、手工模式、退出协同和生成后的预览复用同一更新路径。模板占位符不自动当作已确认值，未修改的空字段保留模板占位。
- 工具同时返回精确ID和值标签时优先精确ID；收到精确结果后不再用自由文本猜测覆盖它。
- 模板预览和生成后预览忽略过期回复，切换模板/新建会话后不会被旧请求写回；切换模板时清空上一模板的字段与产物。
- 修复重试按钮使用旧CSS选择器找不到原请求的问题，改为直接保留本次请求文本。
- 补上预览进度容器；新对话兼容该容器尚未挂载的情况。删除无调用的旧包装函数和空函数，动画样式统一放入CSS。

脚本采用按序加载的普通`defer`脚本，保留页面现有内联事件入口；共享状态仍集中在`state.js`，本轮没有声称实现完整模块隔离。

## Word 填写引擎

- `doc_builder.py`将内置/自定义模板重复的字段分类、复选框避让、段落、表格、行组、XML修复与保存合并为一条公共流程；两种数据展开策略及四元组返回接口保留。
- `field_values.py`统一字段ID优先、标签兼容的取值规则，表格、段落和多列字段复用；None不再写成字面量“None”，0/False仍可填写。
- 多列字段支持字段ID，并优先于同名标签数据。
- `colon_filler.py`合并重复的行/单元格定位代码，保留原有追加、替换和日期处理分支。
- 内置数据展开先复制输入，避免考勤映射删除调用者的数据。
- 清除填写子模块20处无用导入；保留旧工具入口和依赖版本。

## 保留的边界

这是一轮有验证的旧代码整理，不代表全库技术债已清零。前端仍有内联事件、共享状态、基于文本的旧工作流兼容解析，打印代码仍较长；旧工具模块仍保留兼容导出。模板识别、复杂行组定位、跨模板准确率与多用户状态生命周期问题需要后续分别处理。浏览器验收使用手工填写，没有为本次清理重复运行付费模型A/B。

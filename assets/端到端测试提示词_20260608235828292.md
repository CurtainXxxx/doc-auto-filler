# 端到端全链路测试提示词

## 测试背景

你现在需要对我的"智填教务"多Agent文档填充系统进行端到端全链路测试。

**这是完整的用户对话流程测试：模拟真实用户在聊天中上传文件、发送指令，让 Router → 知识提取Agent → 填充Agent → 生成Agent 全链路自动跑完。**

---

## 第0步：平台摸底（先做这一步，再做测试）

在正式测试之前，先扫描你当前能访问到的所有文件，告诉我实际有什么。

### 0.1 列出所有模板文件（.docx）
把你所在环境能访问到的所有 docx 模板文件列出来，报告：
- 完整文件名
- 文件大小

### 0.2 列出所有知识文件（.txt）
列出所有 txt 知识文件，按模板分组，报告每个模板有哪些难度：
- 模板A有哪些知识文件：简单/中等/困难/示例？
- 模板B有哪些知识文件：简单/中等/困难/示例？
- ...

### 0.3 分析每个模板的字段数
对每个模板文件，调用 `analyze_template` 工具，报告每个模板的实际可填字段数量。

### 0.4 生成测试矩阵
根据以上实际数据，自动生成测试矩阵。格式：
```
| 编号 | 模板文件 | 知识文件 | 字段数 |
|------|---------|---------|--------|
| T1  | 实际文件名 | 实际知识文件名 | 实际字段数 |
| T2  | ... | ... | ... |
```

**原则**：
- 每个模板 × 每个可用难度 = 一项测试
- 有三级全测，只有两级就测两级
- 示例文件不参与测试
- 测试编号按 T1、T2、T3... 顺序

### 0.5 检查知识文件日期
快速扫描所有知识文件中出现的日期，确认都带了年份（如"2024年3月10号"而非"3月10号"）。如有遗漏，列出。

## 执行测试

**按第0步生成的测试矩阵，逐项测试。一项做完再做下一项。**

### 每项测试步骤

**步骤1：上传文件**
- 上传这项测试的模板文件（.docx）
- 上传对应的知识文件（.txt）

**步骤2：发送填充指令**
> 帮我用刚才上传的知识文件内容填充这个模板

**步骤3：观察全链路**
确认系统依次执行：
1. Router 识别意图
2. 知识提取Agent 输出 `[知识提取完成]`
3. 填充Agent 输出 `[填充完成]`
4. 生成Agent 输出 `[生成完成]`
5. 返回可下载的 docx 文件

**步骤4：下载并检查**
- 下载生成的 docx 文件
- 打开查看字段填充情况
- 检查格式是否保留（合并单元格、复选框等）

**步骤5：记录结果 + Token**

每一项LLM调用都要记录token。Coze平台每次LLM响应中包含 `usage`：
```json
{"usage": {"prompt_tokens": xxx, "completion_tokens": xxx, "total_tokens": xxx}}
```

分别记录每个Agent阶段的token消耗（Router / 知识提取 / 填充 / 生成）。

报告格式：
```
## T1 [模板名]_[难度] - X字段
| 阶段 | 状态 | 耗时 | prompt_tokens | completion_tokens |
|------|------|------|---------------|--------------------|
| Router路由 | ✅/❌ | Xs | X | X |
| 知识提取 | ✅/❌ | Xs | X | X |
| 字段填充 | ✅/❌ | Xs | X | X |
| 文档生成 | ✅/❌ | Xs | X | X |
| 文件下载 | ✅/❌ | — | — | — |

填充结果：
- 已填充字段：X/X
- 未填充字段：X（列出字段名）
- 填充率：XX.X%

Token汇总：
- 总prompt_tokens：X / 总completion_tokens：X / 总tokens：X

格式检查：
- 合并单元格：✅/❌
- 复选框：✅/❌（如涉及）
- 动态表格行：✅/❌（如涉及）

备注：（如有异常、错填、乱填请记录）
```

## Token成本计算

测试完成后，按实际使用的模型定价计算成本。

**先确认你当前使用的实际模型名称**。然后按以下公式算：
```
输入成本 = prompt_tokens / 1,000,000 × 输入单价
输出成本 = completion_tokens / 1,000,000 × 输出单价
总成本 = 输入成本 + 输出成本
```

**对比方案定价（供PPT用）**：

| 方案 | 输入 ¥/1M tokens | 输出 ¥/1M tokens |
|------|------------------|-------------------|
| GPT-4o | 72 | 108 |
| Claude Opus 4 | 108 | 216 |

## 注意事项

1. 逐项测试，不并发；一项完成后再开始下一项
2. 超时（>180秒无响应）记录为❌，跳过继续下一项。评价报告等复杂模板全链路实测在60-180秒之间，120秒会导致正常慢速测试误判
3. 字段明显错填（如姓名填到学号字段），备注里标注
4. 由于当前系统输出没有置信度分数，填充结果按"已填充/未填充"二分统计，不区分Confirmed/Review/Empty
5. 如果某模板有多个版本的知识文件但只用了一部分，说明原因

## 每项测试的执行流程

**逐项测试，一项做完再做下一项。每项测试的步骤：**

### 步骤1：上传文件
- 上传这组测试的**模板文件**（.docx）
- 上传对应的**知识文件**（.txt）
- 模板文件路径：`projects/assets/templates/` 或 `测试文件/`
- 知识文件路径：`projects/assets/knowledge/<模板名>/`

### 步骤2：发送填充指令
上传完文件后，发送指令：
> 帮我用刚才上传的知识文件内容填充这个模板

### 步骤3：观察全链路流程
确认系统依次执行了：
1. Router 识别意图
2. 知识提取Agent 输出 `[知识提取完成]`
3. 填充Agent 输出 `[填充完成]`
4. 生成Agent 输出 `[生成完成]`
5. 返回可下载的 docx 文件

### 步骤4：下载并检查
- 下载生成的 docx 文件
- 打开查看字段填充情况
- 检查格式是否保留（合并单元格、复选框等）

### 步骤5：记录结果（含Token消耗）

每一项LLM调用都要记录token数。在Coze平台上，每次LLM调用的响应中会包含 `usage` 字段：
```json
"usage": {
  "prompt_tokens": xxx,
  "completion_tokens": xxx,
  "total_tokens": xxx
}
```

请分别记录每个Agent阶段的token消耗：
- **Router阶段**：意图识别消耗的token
- **知识提取Agent阶段**：提取字段信息消耗的token
- **填充Agent阶段**：匹配字段值消耗的token
- **生成Agent阶段**：生成docx消耗的token

按以下格式报告每项测试：

## 全链路测试的判断标准

| 成功标准 | 说明 |
|---------|------|
| 全链路无报错 | Router正确路由、三个Agent依次执行、无超时或截断 |
| 生成可下载的docx | 文件不为空、能正常打开 |
| 字段有填充 | 填充率 > 0%（至少确认Agent在工作） |
| 格式保留 | 合并单元格未重复展开、复选框状态正确 |

**核心指标**：
- **端到端完成率**：能走完完整链路并生成docx的测试数 / 16
- **平均填充率**：所有完成的测试的 confirmed / total_fields
- **格式保留率**：格式正确的测试数 / 完成的测试数
- **单文档成本**：总成本 / 完成测试数
- **成本-准确率性价比**：填充率 / 成本

---

## 注意事项

1. 逐项测试，不要并发；一项完成后再开始下一项
2. 如果某项超时（>120秒无响应），记录为❌超时，跳过继续下一项
3. 如果生成的docx字段明显错填（如姓名填到学号字段），在备注里标注
4. 测试完成后，汇总一份总表
